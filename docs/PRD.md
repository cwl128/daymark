# Daymark V1.0 产品需求

免费、Apache-2.0 开源、离线优先的 macOS / Windows 日历与 Todo。无需账号、付费 API、服务器或联网。版本 0.1.0 是向 V1.0 迭代的首个实现，不等同于跨平台稳定版验收完成。

## 验收范围

1. React / TypeScript + Tauri 2 可启动、可构建；SQLite 持久化；README、完整许可证和本地 Git 提交。
2. 日程和任务可新增、编辑、删除、设置开始/结束/截止时间和完成；日历日视图；重启后保留。
3. 独立原生悬浮窗可在屏幕左/右边缘收放；展示今天安排、下一项倒计时、勾选完成、每日进度；所有窗口即时同步。
4. Rust 常驻后台按 SQLite 状态检查提前 10 / 5 分钟提醒；系统通知权限可见；已完成或删除取消后续提醒；启动和睡眠恢复重新计算。
5. 前 1 分钟展示可退出全屏窗口：完成、暂缓 5 分钟、关闭以及 Escape。禁止锁住用户或拦截系统快捷键。
6. 周/月视图、日期导航；提醒提前时间、系统声音/静音、侧边位置、全屏开关本地保存。
7. 前端和 Rust 单元测试、实际桌面启动、跨平台 CI、标签触发 GitHub Releases 草稿；macOS DMG / Windows NSIS。

## 数据与提醒规则

单次日程/任务，时间以 UTC 秒持久化，按系统时区显示。日程必须有开始和结束；任务至少有开始或截止；提醒基准为日程开始、任务截止（无截止则开始）。V1 不含重复事件、云同步、共享日历、拖拽排程和自定义音频导入。

标题、备注、开始、结束、截止、完成时间、修改版本、暂缓时间存入 SQLite。完成时间用于每日进度；跨午夜日程会出现在每个相交日期。无开始时间的任务按截止日期显示。覆盖更新需要匹配版本，防止多窗口静默丢失修改。

后台每秒按当前系统时钟重新读取待提醒记录，不依赖前端定时器。所有时刻为绝对时间；时区变化只改变显示和日期归属，不改变已经安排的绝对时刻。睡眠恢复或重启后只补发最近 15 分钟内最紧迫的一档，跳过更早档位以避免连发；超过 15 分钟记录为过期，不轰炸历史提醒。提醒投递记录持久化，以事件版本和档位去重；投递失败保留重试。系统通知和落库无法跨系统原子提交，崩溃于两者之间可能重发一次。

应用主窗关闭后隐藏并继续运行，可从菜单栏/系统托盘重新打开或退出；退出应用、关机或睡眠期间不能唤醒设备，也不能保证准点投递。操作系统通知权限、勿扰模式和声音设置可能影响展示。声音选项只提供系统默认/静音，跨平台自定义铃声留待后续验证。

## 交付边界

本机验证 macOS ARM64；Windows 通过 CI 编译测试并保留真机手工验收项。免费安装包可不签名；不声称免系统安全提示。Apple 公证和可信 Windows 签名需要额外凭据，不作为免费原型的依赖。

## 开发阶段

Phase 1 初始化与文档 → Phase 2 SQLite/CRUD/日视图 → Phase 3 边缘窗/同步 → Phase 4 后台调度 → Phase 5 全屏 → Phase 6 周月/设置 → Phase 7 测试/安装包/发行。每阶段在 docs/VALIDATION.md 记录实际证据与剩余阻碍。

## 0.1.1 修复范围

保持所有日程与完成记录；新增设置字段以默认值兼容旧 JSON，后台事务合并设置补丁，避免窗口互相覆盖。侧栏由 Rust 管理启用、收起、展开与固定状态，原生尺寸与工作区缩放约束见 DESIGN.md。通知使用 macOS UserNotifications / Windows ToastNotifier.Setting 的实际权限，测试和正式提醒共用发送服务；申请权限由用户明确触发，自测由后台倒计时五秒。系统接受投递不能视为收到。三步引导仅保存版本号，不创建真实数据。主题、强调色与浅深背景可配置，同步所有窗口并响应系统主题。

0.1.1 的公开发行门槛是核心原生流程实际观察通过；自动化、编译与人工验收分别记录于 VALIDATION.md。不增加背景图片、透明度、布局编辑或云同步。

## 0.1.2 简单待办修复

任务默认只需标题。可选一个提醒钟点（24 小时制），可选仅一次／每天；仅一次的日期自动填入，无需伪造起止时间或截止时间。需要真正截止时间时在更多选项勾选。日程仍使用起止时间。

每日规则保存本地开始日期与钟点，不生成无限条记录；每个日期独立保存完成与暂缓。修改规则作用于整个系列并保留完成记录，删除确认整个系列。日、周、月视图投影当天实例，侧栏与主窗共用数据及按天完成接口。后台每秒按系统时区重新计算昨天、今天、明天的实例，复用现有投递去重、提前提醒和全屏提醒；在时间点额外发系统通知。夏令时跳过的钟点顺延到当天首个有效分钟，重复小时只取第一次。普通未定时任务不排提醒。

SQLite 升级只增加 scheduled_at、recurrence 及 occurrence_states 表，不替换旧数据；旧任务原有开始／截止时间的编辑和提醒继续兼容。
